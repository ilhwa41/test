# 06. 디자인 방향

> 발주 타이밍 알림 시스템 기획 문서 · 2026-11-07 · 근거: 프로젝트 회의(바이브코딩 팀), 시안 이미지

## 1. 선택한 컨셉

**"업무 중심형 (실무자 친화적)"** — 업무 흐름에 맞춘 작업 중심 UI

- 참고 이미지: `design/스크린샷 2026-11-07 오후 4.26.54.jpg` (docs 폴더 안 `design` 폴더)

![업무 중심형 시안](<design/스크린샷 2026-11-07 오후 4.26.54.jpg>)

### 이 컨셉이 기획과 맞는 이유
- 첫 화면에서 **"사용 입력 / 입고 입력"** 버튼이 바로 보인다. v1의 핵심이 매일 수량을 입력하는 일이라 가장 자주 쓰는 동작이 맨 앞에 온다.
- **"알림이 필요한 품목"** 이 따로 모여 있어서, 회의에서 나온 "그 언저리에 한마디 해주면 좋겠다"는 요구에 맞다.
- 남은 수량, D-숫자(소진 예상일), 상태 배지, 막대가 한 카드에 같이 있어서 한눈에 읽힌다.
- 최근 활동 내역이 있어서 "내가 오늘 입력했나"를 바로 확인할 수 있다. 발주를 깜빡하는 문제와 같은 종류의 실수를 줄인다.
- 장식이 적고 업무용으로 깔끔해서 "단순하게 시작한다"는 팀 방향과 맞다.

| 영역 | 내용 |
|---|---|
| 좌측 사이드바 | 로고(발주 알림), 메뉴: 대시보드(선택됨) / 입력하기 / 발주 기록 / 설정 |
| 상단 바 | 오늘 날짜 표시, 알림 벨, 사용자 이름("대표님") 메뉴 |

| 빠른 입력 버튼 | 사용 입력(파랑) / 입고 입력(초록) / 품목 추가(흰색) |

### 상태별 표시 규칙
| 상태 | 배지 글자 | 색 | 의미 |
|---|---|---|---|
| 정상 | 정상 | 초록 | 발주점보다 충분히 많음 |
| 주의 | 주의 | 주황 | 발주점에 가까워짐 |
| 발주 필요 | 발주 필요 | 빨강 | 발주점 이하 |
| 긴급 | 긴급 | 진한 빨강 (배지 배경 `#D7373F`, 글자 흰색) | 긴급 알림 기준 이하. **시안에 없음**, 제안 |
| 입고 대기 | 입고 대기 | 보라 | 발주 완료, 입고 기다리는 중 (알림 멈춤) |

- 상태는 **색 + 글자 + 막대** 세 가지로 함께 표시해서, 색을 구분하기 어려운 사람도 글자로 알 수 있게 한다.
- D-숫자는 **발주 필요일 때만 빨강**으로 강조한다. 시안에서 "D-3"은 빨강, "D-12"(주의)는 일반 글자색이다.

## 4. 글꼴과 글자 크기

- 글꼴: 한글 산세리프. **Pretendard**를 기본으로, 없으면 Noto Sans KR → 시스템 기본 글꼴 순서. (시안의 글자 모양이 이 계열과 비슷하다.)
- 제목은 굵게(Bold), 본문은 보통(Regular)으로, 굵기 차이로 위계를 만든다.

| 요소 | 크기 | 굵기 |
|---|---|---|
| 인사 배너 제목 | 24px | Bold |
| 섹션 제목 ("알림이 필요한 품목") | 20px | Bold |
| 버튼 글자 | 18px | Bold |
| 카드의 품목명 | 18px | Bold |
| 남은 수량, D-숫자 | 16px | D-숫자는 Bold |
| 상태 배지 | 14px | Bold |
| 활동 내역 제목 | 15px | Medium |
| 날짜·시간, 보조 설명 | 13px | Regular |

- 가장 작은 글자도 13px 아래로 내리지 않는다. 이동 중에도 읽을 수 있어야 한다.

## 5. 레이아웃 원칙

1. **위에서 아래로 "지금 할 일" 순서**: 인사·요약 → 빠른 입력 버튼 → 알림이 필요한 품목 → 최근 활동.
2. **큰 화면**: 왼쪽에 사이드바(약 220px)를 고정하고, 본문은 2열(알림 품목 약 60% / 최근 활동 약 40%)로 나눈다.
3. **버튼**: 높이 약 56px, 가로로 3개. 사용 입력은 파랑 채움, 입고 입력은 초록 채움, 품목 추가는 흰 바탕에 옅은 테두리로 가장 약하게 보이게 한다.
4. **카드**: 흰 바탕, 모서리 둥글게(약 16px), 옅은 그림자, 안쪽 여백 약 20px, 카드 사이 간격 12~16px.
5. **상태 배지**: 알약 모양(완전히 둥근 모서리), 카드 오른쪽 위.
6. **정렬**: 알림이 필요한 품목은 **발주가 급한 순서**(D-숫자가 작은 순)로 보인다.
7. **아이콘**: 단순한 단색 아이콘을 둥근 배경 위에 둔다. 활동 내역에서는 입고 = 초록 체크, 사용 = 파랑 연필로 구분한다.
8. **여백**: 영역 사이는 충분히 띄워서 답답하지 않게 한다. 장식은 최소로 한다.

## 6. 모바일 대응 (시안에 없는 부분)

시안은 **큰 화면(웹) 기준**입니다. 그런데 회의에서 대표가 이동 중이거나 통화 중에도 확인해야 한다는 이야기가 나왔으므로, 작은 화면에서도 같은 구성이 되도록 규칙을 정합니다.

| 큰 화면 | 작은 화면 (약 768px 미만) |
|---|---|
| 좌측 사이드바 | **하단 탭 4개** (대시보드 / 입력하기 / 발주 기록 / 설정) |
| 버튼 3개 가로 배치 | 사용 입력·입고 입력을 한 줄에 나란히, 품목 추가는 그 아래 전체 폭 |
| 본문 2열 | **1열**: 알림이 필요한 품목 먼저, 최근 활동은 아래 |
| 상단 바의 날짜·벨·이름 | 날짜는 숨기고 벨과 이름만 남김 |

- 터치할 수 있는 모든 요소는 높이를 **최소 44px** 이상으로 한다.
- 이메일 알림의 링크를 눌렀을 때 바로 해당 품목 화면이 열리게 한다. (03-screens.md 흐름과 같음)

## 7. 시안과 기획이 다른 부분

시안을 그대로 쓰지 않고 고쳐야 하는 곳입니다.

| 번호 | 시안 | 정리 |
|---|---|---|
| 1 | 인사 배너가 "현재 5개 품목이 정상적으로 관리되고 있습니다"인데, 바로 아래에는 발주 필요·주의 품목이 있다. | 배너 문구는 상태에 따라 바뀐다. 발주 필요 품목이 있으면 "발주가 필요한 품목이 N개 있어요"로 바꾸고 아이콘도 경고 색(빨강·주황)으로 바꾼다. 모두 정상일 때만 "오늘도 수고 많으세요!"와 초록 체크를 쓴다. |
| 2 | 상단 날짜는 "2026.11.07 (토)"인데 활동 내역에는 "11.07 (목)"이 있다. 요일이 맞지 않는다. | 시안의 실수로 보고 따르지 않는다. 요일은 날짜에서 계산해서 표시한다. |
| 3 | 메뉴가 "대시보드 / 입력하기 / 발주 기록 / 설정"이다. 03-screens.md의 이전 버전에는 "홈 / 품목 / 발주 기록 / 설정"으로 적혀 있었다. | 시안의 메뉴 이름을 따른다. 품목 전체 목록은 "알림이 필요한 품목"의 **전체 보기**로, 새 품목은 **품목 추가** 버튼으로 연결한다. (03-screens.md에 반영함) |
| 4 | 시안에 "입고 대기" 상태가 없다. | 3장(색상)에 적은 보라 계열 스타일을 추가한다. |
| 5 | 최근 활동 내역의 "전체 보기" 화면이 03-screens.md에 없다. | 활동 기록 전체 목록 화면을 추가한다. 데이터는 `stockLogs`를 그대로 쓰므로 데이터 모델 변경은 없다. |
| 6 | 품목마다 일러스트(원사 실타래, 포장 박스)가 있다. | v1은 **기본 아이콘 몇 종 중 선택**으로 한다. 사진 업로드는 범위 밖이다. |
| 7 | 인사 배너 오른쪽의 공장 일러스트, 사용자 프로필 사진 | v1에서는 생략할 수 있다. 사용자 이름만 표시한다. |
| 8 | 알림 벨 | 눌렀을 때 `alerts`(알림 기록)의 최근 목록이 열리는 것으로 한다. |
| 9 | 카드 아래 막대의 기준이 시안만으로는 알 수 없다. | **현재 재고 ÷ 최대 보관량**으로 채우고, 발주점 위치에 작은 눈금을 표시하는 것으로 제안한다. 확정이 필요하다. |
