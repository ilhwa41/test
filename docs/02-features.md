# 02. 핵심 기능

> 발주 타이밍 알림 시스템 기획 문서 · 2026-11-07 · 근거: 프로젝트 회의(바이브코딩 팀)

## 발주 시점 규칙 (v1 기본 규칙)

알림 기준은 **대표가 품목마다 직접 정한 수량**으로 한다. 회의에서 대표가 실제로 쓰는 방식이 이것이다.

| 기준 | 의미 | 원사 예시 |
|---|---|---|
| 발주 알림 기준 (발주점) | 남은 수량이 이 값 **이하**면 "발주할 때" 알림 | 400개 |
| 긴급 알림 기준 | 남은 수량이 이 값 **이하**면 "긴급 주문" 알림 | 200개 |

### 원사 사례 (회의에서 정해진 값)
- 제품 1개를 만들 때 원사 **10개** 사용
- 한 번 입고되는 양: 1,000개 (40피트 컨테이너 1개)
- 발주 후 입고까지: 약 3주~한 달
- 보관 공간: 컨테이너 1개 분량까지만 가능. 이 한도는 **최대 보관량** 항목으로 입력한다.
- 발주 알림 기준 400개, 긴급 알림 기준 200개

### 추천 발주점 (참고용)
품목 입력 화면에서 아래 계산식의 결과를 "추천 발주점"으로 **참고로만** 보여준다. 자동으로 적용하지 않고, 대표가 직접 입력한 값이 항상 우선한다.

```
추천 발주점 = (하루 사용량 × 입고까지 걸리는 일수) + 안전재고
```

> **숫자가 서로 맞지 않는 부분 (확인 필요)**
> 회의의 가정(하루에 제품 10개 생산)대로면 원사는 하루 100개가 쓰인다. 그러면 발주 기준 400개는 약 4일치, 긴급 기준 200개는 약 2일치다. 입고까지 3주~한 달이 걸리는 것과 맞지 않고, 추천 발주점도 약 2,100~3,000개 이상으로 최대 보관량을 훨씬 넘는다.
> 회의의 "하루 10개"는 예를 든 숫자였으므로, **실제 하루 평균 사용량**을 확인해야 한다. 확인될 때까지 v1은 대표가 정한 기준(400 / 200)을 그대로 따른다. (`08-open-questions.md` 참고)

## 1단계에 반드시 들어갈 기능
1. **품목 등록**: 이름, 단위, 발주처, 최대 보관량, 리드타임, 하루 사용량, **발주 알림 기준, 긴급 알림 기준**
2. **재고 수량 표시**: 현재 남은 수량을 한눈에
3. **사용 수량 입력**: 오늘 몇 개 썼는지 수기로 입력
4. **입고 수량 입력**: 몇 개가 들어왔는지 입력 (입고하면 재고가 올라감)
5. **발주 알림과 긴급 알림**: 남은 수량이 발주 기준 이하가 되면 발주 알림, 긴급 기준 이하가 되면 긴급 알림을 이메일로 보낸다.
6. **중복 알림 방지와 재알림**: 같은 날 반복해서 울리지 않고, 발주 확인을 누르기 전에는 하루 간격으로 다시 알림
7. **발주 완료 체크**: "발주했음"을 누르면 발주 수량과 입고 예정일을 기록하고, 입고 대기 중에는 발주 알림을 멈춤. 단, **긴급 알림은 입고 대기 중에도 보낸다.** (입고가 늦어지는 경우를 놓치지 않기 위해. 보내는 문구에 "이미 발주함, 입고 예정일 ○○"을 함께 적는다.)
8. **소진 예상일 표시**: 지금 속도로 쓰면 며칠 뒤에 바닥나는지 표시
9. **로그인**: 본인만 접근할 수 있게 한다 (대표 1인 사용 기준)

## 나중으로 미룰 기능
| 단계 | 기능 |
|---|---|
| v2 | 식당 모드: 메뉴별 판매 수량 × 1인분 용량(예: 오겹살 1인분 몇 g)으로 재료 소진량 자동 계산 |
| v2 | 생산 수량으로 사용량 자동 계산: 사용 입력에서 "제품 N개 생산"을 넣으면 원사 사용량(N × 제품당 사용량 10개)을 자동으로 계산 |
| v2 | 발주처별 연락 방식에 맞춘 발주서 초안 작성 (메일, 문자, 카톡용 문구) |
| v2 | 카카오톡·문자 알림 |
| v3 | 생활용품 모드: 구매 주기 기반 알림 (휴지, 세제, 계란 등), 가구 인원별 기본 사용량 |
| v3 | 구매 이력을 바탕으로 한 주기 추천과 정기 주문 제안 |
| 이후 | 여러 사용자 공유, 사진·바코드 입력, 통계 화면 |
