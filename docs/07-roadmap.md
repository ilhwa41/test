# 07. 개발 순서 (로드맵)

> 발주 타이밍 알림 시스템 기획 문서 · 2026-11-07 · 근거: 프로젝트 회의(바이브코딩 팀)

## v1 — 사업장 발주 알림 (원사 사례 기준)
| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| 0 | 환경설정, 빈 프로젝트 배포 | 로컬과 Vercel에서 첫 화면이 열린다 |
| 1 | 로그인, 품목 등록·수정·삭제 | 품목 목록이 저장되고 다시 열어도 남아 있다 |
| 2 | 사용·입고 입력과 재고 기록 | 입력하면 재고가 바뀌고 기록이 남는다 |
| 3 | 발주·긴급 기준에 따른 상태 표시, 소진 예상일 | 대시보드에서 상태(정상·주의·발주 필요·긴급)와 D-숫자가 맞게 보인다 |
| 4 | 이메일 알림 (Cron), 긴급 알림, 중복 방지·재알림 | 400개 이하이면 발주 알림, 200개 이하이면 긴급 알림 메일이 오고 같은 날 반복되지 않는다 |
| 5 | 발주 완료 체크, 입고 대기, 입고 처리 | 발주 후에는 발주 알림이 멈추고(긴급은 계속), 입고하면 재고가 오른다 |
| 6 | **실제 수치로 시험 운영** | 원사 입고 1,000개, 발주 400 / 긴급 200 기준으로 몇 주 돌려 보고, 실제 하루 사용량으로 기준값이 현실과 맞는지 확인 |
