# 발주 알림 (1차)

재고와 사용 속도를 보고 발주 시점을 보여주는 웹앱입니다. 기획 문서는 상위 폴더의 `docs/`에 있습니다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. Firebase 웹 설정값은 `src/lib/firebase.ts`에 들어 있어 바로 프로젝트 `test-1ef99`에 연결됩니다. 이 값은 비밀이 아니라 브라우저에 공개되는 앱 식별값이고, 데이터는 로그인과 `firestore.rules`로 보호합니다.

## 확인

```bash
npm test
npm run lint
npm run build
```

## Firebase 연결

1. Firebase 콘솔에서 프로젝트를 만들고 웹 앱을 추가합니다.
2. Authentication에서 **이메일/비밀번호** 로그인을 켜고, Users 탭에서 대표 계정을 직접 만듭니다. 앱에는 회원가입 화면이 없습니다.
3. Firestore Database를 위치 `asia-northeast3`(서울)로 만듭니다. 위치는 나중에 바꿀 수 없습니다. 만들지 않고 5번을 실행하면 미국 위치로 자동 생성됩니다.
4. 다른 Firebase 프로젝트를 쓸 때만 `.env.example`을 `.env.local`로 복사하고 웹 앱 설정 값을 넣습니다. 이 값이 코드의 기본값보다 우선합니다.
5. 보안 규칙과 인덱스를 올립니다.

```bash
npx firebase-tools login
```

```bash
npx firebase-tools deploy --only firestore --project <프로젝트-ID>
```

처음 올린 인덱스는 완성까지 몇 분 걸립니다. 그동안 대시보드에 "데이터를 불러오지 못했어요"가 나올 수 있습니다.

## 1차 범위

- 포함: 로그인, 품목 등록·수정·삭제, 사용·입고 입력, 재고 보정, 상태 표시, 소진 예상일, 활동 기록
- 2차: 이메일 알림, 발주 완료, 입고 대기, 입고 처리, 발주 기록, 설정, 알림 기록

## 기획 문서와 다르게 둔 부분

- 주의 상태는 발주 기준의 1.5배 이하로 임시로 정했습니다 (`src/lib/inventory.ts`).
- 품목 상태는 저장하지 않고 재고에서 매번 계산합니다.
- 발주처는 별도 관리 화면이 없어 품목에 이름만 적습니다.
- 재고 보정은 품목 수정에서 현재 재고를 바꾸면 기록됩니다.
- 하루 사용량을 비워 두면 최근 14일 사용 기록의 평균을 씁니다.
